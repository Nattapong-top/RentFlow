# Git Standard

### กฎการ Commit (Atomic Commits)

เพื่อให้ประวัติการทำงานของโครงการสะอาดและปลอดภัย จุกจะยึดหลักการ Atomic Commit ดังนี้:

1. **หนึ่ง Commit = หนึ่งงาน:** ห้ามนำงานหลาย Feature หรือการ Refactor หลายอย่างมาปนใน Commit เดียวกัน
2. **สถานะต้องสมบูรณ์:** Commit ต้องมีขนาดเล็กพอที่จะตรวจสอบได้ง่าย แต่ต้องใหญ่พอที่ทำให้โปรเจคยังทำงานได้ (ผ่าน
   `make all-tests`) ในสถานะของ Commit นั้นเสมอ
3. **ข้อความชัดเจน:** ใช้รูปแบบ Conventional Commit เพื่อระบุสิ่งที่ทำอย่างตรงไปตรงมา (เช่น `feat: ...`, `fix: ...`,
   `refactor: ...`, `test: ...`, `docs: ...`)
4. **กระบวนการ:** ต้องรัน `make all-tests` และผ่านก่อนทำการ commit ทุกครั้ง ถ้าไม่มีปัญหาอะไรให้ใช้คำสั่ง make merge
   เพื่อรวมโค๊ดเข้า Master
